## Реестр типов нод

Паттерн имени файла: `<name>.<type>.md`. Суффикс перед `.md` = тип ноды.
Агент по суффиксу однозначно определяет тип, не открывая файл.

| Слой        | `AWN-TYPE` (тип ноды) | Маска имени файла | Где живёт                  | Описание                                                   | Родитель                 | **Добавляется в реестр нод** |
| ----------- | --------------------- | ----------------- | -------------------------- | ---------------------------------------------------------- | ------------------------ | ---------------------------- |
| 0. Vault    | —                     | —                 | корень                     | Корень хранилища                                           | — (корень)               | —                            |
| 1. Space    | Space                 | `_index.node.md`  | `space-*/`                 | Самостоятельная область знаний (может вкладывать Space)    | Vault, Space             | Да                           |
| 2. Part     | Part                  | `*.node.md`       | внутри Space               | Атомарная самостоятельная сущность                         | Space                    | Да                           |
| 3. Memory   | Note                  | `*.note.md`       | `inbox/` или `notes/`      | Сырая входящая заметка (поток времени)                     | Space                    | Нет                          |
| 3. Memory   | Page                  | `*.page.md`       | `pages/`                   | Переработанное знание (страница книги)                     | Space                    | Нет                          |
| 3. Memory   | Row                   | `*.row.md`        | `databases/<type>/`        | Строка таблицы базы данных                                 | Space                    | Нет                          |
| 3. Memory   | Sidecar               | `*.sidecar.md`    | рядом с не-md файлом       | Описание не-md файла (медиа, документ, бинарь)             | Space (спутник external) | Нет                          |
| 3. Memory   | Volume                | `*.volume.md`     | рядом с родительской нодой | Приватная память ноды (грузится по запросу)                | Space, Part (спутник)    | Нет                          |
| 4. View     | View                  | `*.view.md`       | `views/<type>/`            | Проекция над слоями 1–3, 5 (list/kanban/dashboard/mindmap) | Space                    | Нет                          |
| 5. External | —                     | любые             | в любой области            | Не-ноды: медиа, бинари, скрипты, конфиги, `*.md` без типа  | Space                    | Нет                          |

**Правила:**

- Space — единственный тип-контейнер. Папка всегда `space-*/`, файл-якорь — `_index.node.md`.
- Space может содержать вложенные Space (группировки), либо контент (Part, Memory, View, External).
- Volume применим только к Space и Part: `<имя>.node.volume.md` или `_index.node.volume.md`.
- Sidecar именуется по полному имени родителя: `photo.jpg.sidecar.md`, `lecture.mp4.sidecar.md`.
- External — всё, что не имеет распознаваемого типа в суффиксе. В граф нод не входит.
- Множественное число (`pages/`, `notes/`, `rows/`) — это **папки**. Сам тип ноды всегда в **единственном числе**.
- Любая вложенность вне колонки «Родитель» — нарушение контракта.
- Space (`_index.node.md`) **не обязательна** — если их нет, агент работает с нодами напрямую по триггерам.

## Реестр нод с автоматизацией для выполнения по расписанию (`AWN-AUTOMATIZATION: true`)

Сводка для планировщика окружения агента (cron, n8n и т.п.): все ноды, у которых в шапке **`AWN-AUTOMATIZATION: true`**, обязаны быть перечислены здесь. Канон расписания — поле **`AWN-CRON`** в самой ноде.

**Синхронизация (агент):** при создании ноды, при включении/выключении автоматизации, при смене `AWN-CRON` или переносе файла — добавить, обновить или удалить строку в этой таблице; путь как в остальном реестре (от **корня проекта**).

## Реестр дополнительных файлов (читать/обновлять по необходимости)

Справочник важных не-нодовых файлов, которые агент может подключать в контекст по явной задаче пользователя или по рабочей необходимости.

| Файл (путь)          | Описание и назначение                                                                                                                         |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `HEARTBEAT.md`       | Операционный файл состояния/пульса системы: фиксирует текущий статус, контрольные сигналы и полезен для быстрой проверки «живости» процессов. |
| DEPENDENCIES.md      | Сохраняем список зависимостей, чтобы не забыть в данный файл. Аналог **requirements.system** — просто текстовый файл со списком пакетов.      |
| `README.md`          | Главный обзор проекта: концепция, структура, базовые правила и точки входа для онбординга.                                                    |
| `.env`               | Переменные окружения для локального запуска и интеграций; источник runtime-настроек и секретов (читать с осторожностью, не публиковать).      |
| `.gitignore`         | Правила исключения файлов из git: что не должно попадать в индекс и коммиты.                                                                  |
| `docker-compose.yml` | Описание локальной контейнерной инфраструктуры: какие сервисы запускаются вместе и с какими параметрами.                                      |
|                      |                                                                                                                                               |
